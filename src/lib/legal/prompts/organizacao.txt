ORGANIZAÇÃO DE DOCUMENTOS — 1 START → 3 UPLOAD
OBJETIVO
Analisar todos os arquivos presentes na pasta 1 Start e compará-los com os arquivos já existentes na pasta 3 Upload.
A pasta 3 Upload é a pasta FINAL que será utilizada para envio ao juiz.
Portanto, o objetivo não é apenas identificar quais documentos devem ser copiados, mas também:
	•	identificar documentos duplicados;
	•	identificar documentos diferentes;
	•	identificar versões mais completas;
	•	preservar todas as informações;
	•	evitar cópias desnecessárias;
	•	evitar perda documental;
	•	converter arquivos quando necessário;
	•	comprimir PDFs quando ultrapassarem 10.000 KB;
	•	agrupar fotos quando aplicável;
	•	organizar a pasta 3 Upload na ordem correta;
	•	utilizar nomenclatura adequada;
	•	validar todos os arquivos criados;
	•	sinalizar situações que necessitem de revisão humana.
A análise deve ser baseada principalmente no CONTEÚDO REAL dos documentos e não apenas nos nomes dos arquivos.

1. ESCOPO E PASTAS
Existem duas pastas principais:
	•	1 Start → pasta de origem;
	•	3 Upload → pasta final/destino que será enviada ao juiz.
1 START
A pasta 1 Start deve ser tratada como SOMENTE LEITURA.
Não é permitido:
	•	apagar arquivos;
	•	mover arquivos;
	•	renomear arquivos;
	•	editar arquivos;
	•	modificar arquivos;
	•	sobrescrever arquivos;
	•	substituir arquivos;
	•	converter os arquivos originais;
	•	comprimir os arquivos originais;
	•	alterar qualquer conteúdo.
Os arquivos originais devem permanecer preservados.
3 UPLOAD
A pasta 3 Upload é a pasta FINAL que será enviada ao juiz.
Os arquivos que já existem nela devem ser preservados.
Não é permitido:
	•	apagar arquivos existentes;
	•	mover arquivos existentes;
	•	modificar arquivos existentes;
	•	sobrescrever arquivos existentes;
	•	substituir silenciosamente documentos existentes.
Se for encontrada uma versão mais completa de um documento já existente, NÃO substituir automaticamente o arquivo antigo.
Nesse caso:
	•	preservar o arquivo antigo;
	•	criar/copiar a nova versão;
	•	utilizar nome diferente;
	•	sinalizar a situação para revisão humana.

2. REGRA ESPECIAL — CONTRATOS ENTRE CLIENTE E ADVOCACIA
Documentos que sejam contratos entre o cliente e a advocacia/escritório NÃO devem ser enviados para 3 Upload.
Isso inclui:
	•	contrato de honorários;
	•	contrato de prestação de serviços advocatícios;
	•	contrato entre cliente e escritório;
	•	contratos equivalentes que formalizem a relação contratual entre cliente e advocacia.
Essa regra possui prioridade sobre as demais regras de cópia, duplicidade, versão ou completude.
Se um desses documentos for encontrado em 1 Start:
	•	não copiar para 3 Upload;
	•	não modificar o original;
	•	não excluir;
	•	não substituir.
Registrar no relatório:
NÃO COPIADO — CONTRATO CLIENTE/ADVOCACIA

3. NÃO FAZER DECISÃO JURÍDICA
O sistema NÃO deve fazer uma decisão jurídica sobre:
	•	relevância jurídica;
	•	validade jurídica;
	•	importância jurídica;
	•	necessidade jurídica;
	•	pertinência jurídica;
	•	suficiência jurídica;
	•	necessidade de protocolo;
	•	possibilidade de descarte de documento.
O sistema não deve decidir, por conta própria, se um documento:
	•	é juridicamente importante;
	•	é necessário para o processo;
	•	pode ser descartado;
	•	deve ou não ser protocolado;
	•	possui validade jurídica;
	•	é suficiente juridicamente.
A função do sistema é aplicar objetivamente as regras deste prompt.
Caso uma situação dependa de interpretação jurídica ou de uma decisão que não esteja claramente determinada pelas regras deste prompt:
REVISÃO MANUAL
Nessa situação:
	•	preservar os arquivos;
	•	não descartar;
	•	não substituir;
	•	não fazer uma conclusão jurídica;
	•	informar a situação no relatório.

4. COMPARAÇÃO PELO CONTEÚDO
Para cada arquivo encontrado em 1 Start:
	1.	Abrir e analisar o arquivo quando tecnicamente possível.
	2.	Analisar seu conteúdo textual.
	3.	Utilizar OCR quando necessário.
	4.	Fazer análise visual quando necessário.
	5.	Identificar o tipo de documento.
	6.	Identificar as informações relevantes.
	7.	Procurar documentos correspondentes em 3 Upload.
	8.	Comparar os documentos pelo conteúdo.
	9.	Identificar se realmente representam o mesmo documento.
	10.	Identificar diferenças relevantes.
	11.	Classificar o arquivo.
	12.	Executar somente a ação autorizada pela classificação.
NUNCA considerar dois arquivos duplicados apenas porque possuem:
	•	o mesmo nome;
	•	nomes semelhantes;
	•	a mesma extensão;
	•	o mesmo tipo;
	•	o mesmo modelo;
	•	o mesmo assunto;
	•	aparência semelhante;
	•	estrutura semelhante.
Documentos do mesmo tipo ou modelo podem pertencer a pessoas, empresas, processos ou situações diferentes.
Exemplo:
CONTRATO JOAO SILVA.pdf
e
CONTRATO MARIA SILVA.pdf
não são duplicados simplesmente porque utilizam o mesmo modelo.

5. ELEMENTOS QUE DEVEM SER CONSIDERADOS NA COMPARAÇÃO
Sempre que disponíveis, considerar:
	•	texto;
	•	OCR;
	•	título;
	•	tipo de documento;
	•	nome das pessoas;
	•	nome das empresas;
	•	CPF;
	•	CNPJ;
	•	RG;
	•	números de processo;
	•	números de contrato;
	•	números de documentos;
	•	datas;
	•	valores;
	•	assinaturas;
	•	carimbos;
	•	cláusulas;
	•	tabelas;
	•	imagens;
	•	anexos;
	•	páginas;
	•	cabeçalhos;
	•	rodapés;
	•	logotipos;
	•	informações complementares;
	•	estrutura do documento;
	•	quantidade de páginas;
	•	conteúdo adicional.
Arquivos com extensões diferentes podem representar o mesmo documento.
Exemplo:
	•	.docx;
	•	.doc;
	•	.txt;
	•	.rtf;
	•	.pdf;
	•	.jpg;
	•	.jpeg;
	•	.png;
podem possuir conteúdo documental equivalente.
A extensão, sozinha, não determina se são documentos diferentes.

6. REGRA ESTRITA PARA DATAS E DIFERENÇAS
Se a DATA apresentada dentro do documento for diferente, mesmo que seja apenas 1 dia, o documento deverá ser considerado diferente.
Exemplo:
Documento A:
01/10/2026
Documento B:
02/10/2026
São documentos diferentes.
Não considerar como duplicado apenas porque todo o restante do conteúdo é semelhante.
É importante diferenciar:
DATA DO DOCUMENTO
A data escrita dentro do próprio documento.
DATA DO ARQUIVO
Data de criação, modificação ou outros metadados do arquivo.
A alteração de metadados do arquivo, por si só, não significa que o documento seja diferente.
Porém, qualquer diferença documental relevante deve ser considerada.
São exemplos de diferenças relevantes:
	•	data;
	•	assinatura;
	•	valor;
	•	número de documento;
	•	número de processo;
	•	CPF/CNPJ;
	•	pessoa;
	•	empresa;
	•	cláusula;
	•	versão;
	•	aditivo;
	•	atualização;
	•	complemento;
	•	páginas adicionais;
	•	anexos adicionais;
	•	conteúdo adicional.
Se existir qualquer diferença relevante ou dúvida sobre a diferença:
REVISÃO MANUAL
Nunca descartar automaticamente um arquivo quando houver dúvida.

7. QUANDO CONSIDERAR UM ARQUIVO DUPLICADO
Um arquivo só poderá ser classificado como duplicado quando:
	1.	o conteúdo documental for efetivamente o mesmo;
	2.	todas as informações relevantes forem equivalentes;
	3.	não existir diferença relevante;
	4.	não existir diferença de data dentro do documento;
	5.	não existir diferença de assinatura;
	6.	não existir diferença de valor;
	7.	não existir diferença de identificadores;
	8.	não existir diferença de pessoa ou empresa;
	9.	não existir diferença de cláusulas;
	10.	não existirem páginas ou anexos relevantes adicionais.
Diferenças puramente técnicas não tornam necessariamente os documentos diferentes, desde que o conteúdo documental seja realmente igual.
Exemplos:
	•	resolução;
	•	qualidade do scan;
	•	compressão;
	•	rotação;
	•	margem;
	•	cor;
	•	qualidade do OCR;
	•	metadados;
	•	pequenas diferenças técnicas de digitalização.
Porém, se a diferença técnica resultar em conteúdo documental diferente, ela deverá ser considerada.

8. VERSÕES MAIS COMPLETAS
Se um arquivo de 1 Start corresponder a um documento existente em 3 Upload, mas possuir páginas ou informações relevantes adicionais, classificá-lo como:
VERSÃO MAIS COMPLETA
PROCEDIMENTO OBRIGATÓRIO
	1.	Preservar o arquivo existente em 3 Upload.
	2.	Não apagar o arquivo antigo.
	3.	Não substituir o arquivo antigo.
	4.	Não sobrescrever o arquivo antigo.
	5.	Copiar a versão mais completa para 3 Upload.
	6.	Utilizar um nome claramente diferente.
	7.	Manter a extensão original, salvo quando houver necessidade de conversão para PDF conforme este prompt.
	8.	Registrar no relatório que existe uma versão anterior e uma versão mais completa.
	9.	Informar quais diferenças foram identificadas.
	10.	Sinalizar a situação para revisão humana.
Nunca apagar uma versão anterior automaticamente apenas porque outra parece mais completa.
EXEMPLO
Se existe:
05 DOCUMENTO.pdf
com 5 páginas em 3 Upload
e em 1 Start existe uma versão correspondente com 8 páginas:
	•	preservar o arquivo de 5 páginas;
	•	copiar a versão de 8 páginas;
	•	utilizar outro nome;
	•	sinalizar que existe uma versão mais completa;
	•	deixar a decisão final para revisão humana.

9. ARQUIVOS QUE CONTÊM VÁRIOS DOCUMENTOS
Se um único arquivo contiver vários documentos diferentes, analisar o conteúdo separadamente sempre que possível.
Se parte do conteúdo já existir em 3 Upload e outra parte for nova, classificar como:
REVISÃO MANUAL — ARQUIVO COM CONTEÚDO MISTO
Preservar o arquivo original.
Não realizar automaticamente:
	•	cortes;
	•	extrações;
	•	exclusões de páginas;
	•	alterações no conteúdo;
	•	edição do documento;
	•	criação de documentos parciais.
Informar no relatório:
	•	quais partes já existem;
	•	quais partes parecem novas;
	•	quais arquivos correspondentes foram encontrados;
	•	qual decisão está pendente.

10. ARQUIVOS QUE NÃO PODEM SER ANALISADOS
Se um arquivo estiver:
	•	corrompido;
	•	protegido por senha;
	•	ilegível;
	•	incompatível;
	•	sem possibilidade de OCR;
	•	sem possibilidade de visualização;
	•	inacessível;
	•	ou não puder ser analisado com segurança;
não assumir que ele é novo.
Também não assumir que ele é duplicado.
Não copiar automaticamente.
Não modificar o original.
Classificar como:
INCERTO — NÃO FOI POSSÍVEL ANALISAR
Registrar:
	•	nome do arquivo;
	•	extensão;
	•	motivo da impossibilidade;
	•	ação necessária para análise.

11. CONVERSÃO DE ARQUIVOS PARA PDF E LIMITE DE 10.000 KB
A pasta 3 Upload é a pasta final que será enviada ao juiz.
Sempre que um arquivo precisar ser preparado para essa pasta e estiver em um formato que possa ser convertido para PDF, a conversão poderá ser realizada.
A conversão deve ocorrer SOMENTE na cópia destinada à pasta 3 Upload.
O arquivo original em 1 Start nunca deve ser alterado.
FORMATOS QUE PODEM SER CONVERTIDOS PARA PDF
Quando aplicável, converter para PDF arquivos como:
	•	.txt;
	•	.doc;
	•	.docx;
	•	.rtf;
	•	.jpg;
	•	.jpeg;
	•	.png;
	•	.webp;
	•	outros formatos compatíveis que possam ser convertidos com segurança para PDF.
REGRA ESPECÍFICA PARA ARQUIVOS DE IMAGEM
Arquivos de imagem, especialmente:
	•	.jpg;
	•	.jpeg;
	•	.png;
	•	.webp;
devem ser convertidos para PDF quando forem destinados à pasta 3 Upload.
A conversão deve preservar a imagem integralmente.
Não:
	•	cortar a imagem;
	•	alterar o conteúdo;
	•	remover partes;
	•	modificar textos presentes na imagem;
	•	alterar a orientação;
	•	reduzir excessivamente a qualidade;
	•	adicionar elementos que não existiam no arquivo original.
Exemplo:
DOCUMENTO.jpg
deve resultar em uma cópia:
DOCUMENTO.pdf
para utilização na 3 Upload.
O arquivo .jpg original deve permanecer preservado em 1 Start.
O mesmo vale para:
DOCUMENTO.jpeg
que deverá resultar em:
DOCUMENTO.pdf
quando destinado à 3 Upload.
ARQUIVOS DE TEXTO E DOCUMENTOS EDITÁVEIS
Arquivos como:
	•	.txt;
	•	.doc;
	•	.docx;
	•	.rtf;
também podem ser convertidos para PDF.
A conversão deve preservar integralmente:
	•	textos;
	•	páginas;
	•	tabelas;
	•	imagens;
	•	assinaturas;
	•	cabeçalhos;
	•	rodapés;
	•	formatação relevante;
	•	informações documentais.
REGRAS DA CONVERSÃO
	1.	Nunca alterar o arquivo original.
	2.	Nunca apagar o arquivo original.
	3.	Nunca substituir o arquivo original.
	4.	A conversão deve ocorrer somente na cópia destinada à 3 Upload.
	5.	Preservar integralmente o conteúdo documental.
	6.	Não remover páginas.
	7.	Não remover informações.
	8.	Não alterar textos.
	9.	Não alterar datas.
	10.	Não alterar valores.
	11.	Não alterar assinaturas.
	12.	Não remover anexos.
	13.	Não modificar o conteúdo das imagens.
	14.	Manter a orientação correta.
	15.	Sempre que possível, preservar a estrutura e apresentação original.
	16.	Após a conversão, validar o PDF gerado.

12. LIMITE DE 10.000 KB
O arquivo final destinado à 3 Upload deve respeitar o limite de:
10.000 KB
Esse limite deve ser considerado especialmente para os PDFs que serão enviados ao juiz.
Se um PDF ultrapassar 10.000 KB, É PERMITIDO comprimir o PDF para reduzir seu tamanho.
A compressão deve:
	•	buscar manter o arquivo abaixo de 10.000 KB;
	•	preservar todas as páginas;
	•	preservar o conteúdo documental;
	•	não remover informações;
	•	não alterar textos;
	•	não alterar datas;
	•	não alterar valores;
	•	não alterar assinaturas;
	•	não remover anexos;
	•	manter o documento legível.
A compressão deve ocorrer somente na cópia destinada à 3 Upload.
O arquivo original nunca deve ser comprimido ou alterado.
VALIDAÇÃO APÓS CONVERSÃO OU COMPRESSÃO
Depois de converter ou comprimir um arquivo:
	1.	verificar se o arquivo existe;
	2.	verificar se abre normalmente;
	3.	verificar se todas as páginas estão presentes;
	4.	verificar se todo o conteúdo foi preservado;
	5.	verificar se o arquivo final possui no máximo 10.000 KB;
	6.	verificar se o arquivo continua legível;
	7.	verificar se a orientação está correta;
	8.	verificar se nenhuma informação foi perdida;
	9.	somente depois considerar o arquivo preparado.
Se a conversão ou compressão causar perda de conteúdo, erro ou corrupção:
ERRO NA CONVERSÃO/COMPRESSÃO
Não considerar o arquivo concluído até que exista uma cópia válida e verificável.

13. AGRUPAMENTO DE FOTOS
Esta é uma exceção específica para fotos/imagens fotográficas.
Identificar quais arquivos são FOTOS REAIS, diferenciando-os de:
	•	prints de tela;
	•	capturas de conversas;
	•	documentos digitalizados;
	•	páginas de documentos;
	•	comprovantes;
	•	imagens que fazem parte de documentos;
	•	screenshots.
FOTOS REAIS
Considerar como foto uma imagem fotográfica propriamente dita, como:
	•	fotografia de uma pessoa;
	•	fotografia de um objeto;
	•	fotografia de um local;
	•	fotografia de produto;
	•	fotografia tirada por celular/câmera;
	•	outras imagens que sejam efetivamente fotografias.
Não considerar automaticamente como foto uma imagem que seja apenas uma captura de tela ou uma página digitalizada.
FOTOS EM ARQUIVOS DE IMAGEM
Se existirem arquivos de imagem como:
	•	.jpg;
	•	.jpeg;
	•	.png;
	•	.webp;
e forem identificados como fotos reais, criar novos PDFs agrupando essas fotos.
FOTOS INDIVIDUAIS EM PDF
Se existirem PDFs que contenham uma única foto real, esses PDFs também podem ser agrupados em novos PDFs.
Agrupar no máximo:
10 FOTOS POR PDF.
Exemplo:
	•	1 a 10 fotos → 1 PDF;
	•	11 a 20 fotos → 2 PDFs;
	•	21 a 30 fotos → 3 PDFs.
REGRAS DO AGRUPAMENTO
	1.	Não alterar os arquivos originais.
	2.	Não apagar os arquivos originais.
	3.	Não substituir os arquivos originais.
	4.	Criar novos PDFs para o agrupamento.
	5.	Agrupar somente fotos reais.
	6.	Não agrupar prints.
	7.	Não agrupar documentos digitalizados.
	8.	Não agrupar páginas de documentos.
	9.	Não misturar fotos com documentos.
	10.	Não misturar fotos com prints.
	11.	Preservar a ordem das fotos quando houver uma ordem identificável.
	12.	Preservar a orientação correta.
	13.	Não cortar as fotos.
	14.	Não editar o conteúdo das fotos.
	15.	Não remover partes das imagens.
	16.	Preservar qualidade suficiente para visualização.
	17.	Utilizar no máximo 10 fotos por PDF.
O objetivo é reduzir a quantidade de arquivos e o espaço ocupado sem modificar os arquivos originais.
LIMITE DE 10.000 KB PARA PDFs DE FOTOS
Os PDFs criados com as fotos também devem respeitar o limite de:
10.000 KB por arquivo.
Se um PDF com até 10 fotos ultrapassar 10.000 KB:
	1.	tentar comprimir o PDF;
	2.	preservar todas as fotos;
	3.	preservar qualidade suficiente para visualização;
	4.	não remover fotos;
	5.	não remover páginas.
Se mesmo após compressão adequada o PDF continuar acima de 10.000 KB, não remover fotos para atingir o limite.
Nesse caso, dividir o conjunto em PDFs menores.
Exemplo:
10 fotos ultrapassam 10.000 KB mesmo após compressão → dividir em dois PDFs com 5 fotos cada.
VALIDAÇÃO
Após criar cada PDF:
	1.	confirmar que o arquivo existe;
	2.	confirmar que abre normalmente;
	3.	confirmar que todas as fotos esperadas estão presentes;
	4.	confirmar que a orientação está correta;
	5.	confirmar que nenhuma foto foi cortada;
	6.	confirmar que nenhuma foto foi perdida;
	7.	confirmar que o conteúdo visual foi preservado;
	8.	confirmar o tamanho do arquivo;
	9.	confirmar que possui no máximo 10.000 KB.
Criar PDFs agrupados com fotos não significa modificar os arquivos originais.

14. ORDEM OBRIGATÓRIA DA PASTA 3 UPLOAD
A pasta 3 Upload é a PASTA FINAL que será enviada ao juiz.
Portanto, os documentos devem seguir uma ordem numérica e lógica de apresentação.
A nomenclatura deve ser:
	•	numerada;
	•	sequencial;
	•	clara;
	•	sem acentos;
	•	adequada à ordem de juntada.
PRIMEIROS DOCUMENTOS — ORDEM FIXA
Os primeiros documentos devem seguir esta ordem:
01 — PROCURACAO
A procuração deve ser sempre o primeiro documento.
Exemplo:
01 PROCURACAO.pdf
02 — DECLARACAO DE HIPOSSUFICIENCIA
A declaração de hipossuficiência deve ser o segundo documento, quando aplicável.
Exemplo:
02 DECLARACAO DE HIPOSSUFICIENCIA.pdf
03 — DOCUMENTO DE IDENTIFICACAO DO CLIENTE
O documento de identificação do cliente deve ser o terceiro documento.
Pode ser:
	•	CNH;
	•	RG;
	•	outro documento oficial de identificação.
Exemplos:
03 DOC ID.pdf
ou
03 CNH.pdf
04 — COMPROVANTE DE RESIDENCIA
O comprovante de residência deve ser o quarto documento.
Exemplo:
04 COMPROVANTE DE RESIDENCIA.pdf
A PARTIR DO 05
A partir do documento 05, organizar os demais documentos conforme a natureza e as necessidades do caso concreto.
Esses documentos podem incluir:
	•	documentos trabalhistas;
	•	documentos civis;
	•	documentos de identificação de outras partes;
	•	documentos de empresas;
	•	contratos pertinentes;
	•	documentos financeiros;
	•	comprovantes;
	•	atestados;
	•	declarações;
	•	documentos processuais;
	•	provas;
	•	anexos;
	•	demais documentos relacionados ao caso.
A ordem a partir do 05 deve ser lógica, coerente e facilitar a compreensão do conjunto documental pelo juiz.

15. EXEMPLO DE ORGANIZAÇÃO — ESFERA TRABALHISTA
Quando se tratar de caso trabalhista, utilizar como referência:
01 PROCURACAO
02 DECLARACAO DE HIPOSSUFICIENCIA
03 DOC ID
04 COMPROVANTE DE RESIDENCIA
A partir do 05, organizar conforme os documentos existentes no caso.
Exemplo:
05 CTPS
06 TRCT
07 FGTS
08 HOLERITE
09 CCT
10 PROVAS
11 ATESTADO MEDICO
12 CNPJ DA RECLAMADA
A sequência pode ser adaptada conforme os documentos efetivamente existentes.
Não inventar documentos que não estejam presentes.

16. EXEMPLO DE ORGANIZAÇÃO — ESFERA CÍVEL
Na esfera cível, os quatro primeiros documentos permanecem:
01 PROCURACAO
02 DECLARACAO DE HIPOSSUFICIENCIA
03 DOC ID
04 COMPROVANTE DE RESIDENCIA
A partir do 05, adaptar a sequência à natureza do caso.
Quando houver documentos de outras partes, como:
	•	genitor;
	•	alimentante;
	•	devedor;
	•	curatelado;
	•	autor;
	•	réu;
	•	outras partes;
organizar os documentos seguindo uma ordem lógica de identificação das partes e, posteriormente, organizar o bloco de provas.
Exemplo conceitual:
05 DOC ID GENITOR
06 COMPROVANTE RESIDENCIA GENITOR
07 DOCUMENTO PARTE
