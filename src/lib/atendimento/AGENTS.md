# Attendance server and domain rules

- Intake defaults to automatic, preserving modes/pauses. Active `ana-prompt.txt` and `ana-restrictions.txt` supply identity with owner training; `ana-scheduling.ts` validates intent, offers and pending-slot consent. Why: no forced greeting or unsafe booking.
- Ana inference uses `ana.functions.ts` with the uploaded `claudeComoSample` adapter; UltraMsg uses channel-validated orchestration, consent and released conversation-owned destinations. Telegram is retired and production restrictions apply before incoming processing and outgoing provider calls. Why: preserve operational safety and provider billing.
- Ana scope is scheduling-only for now: she books, reschedules and cancels; team-only subjects (process, documents, contract, payment, hearings, deadlines) hand off with `encaminhar_humano` and the server's "só dos agendamentos" handoff text; `processo` intent still falls back to draft. Fictional slots are never stored as offers. Why: avoid triage without legal review and keep first offers correct.
- UltraMsg has no interactive lists or buttons (official docs checked 29/10/2026): choices go once in the text as bullets, never numbered and never with "responda com o número"; `textoComOpcoes` only appends offered slots missing from the text. Typed day/time, ordinals and bare numbers still map to the latest offer. Why: clients choose without numeric prompts and the list is never duplicated.
- Process news (`consulta_processo`, testing phase): `consulta-processo.ts` is the single flow for server and simulator. Identify by principal phone only; ask the subject without listing processes; one short notice; draft from server facts only (`ana-redacao-processo.txt`, validated, fallback template); every process fact waits for reviewer approval (AND-xxxx code + hash; ok/corrigir/não; only the configured reviewer or senior/admin); insistence while pending gets "em conferência" (including "??"), agenda keeps working; meaning, chances, values, documents, writes and third parties never consult. Why: confidentiality and no unreviewed legal information.
- Ana test battery: scenarios in `tools/simulador-ana/bateria/cenarios.ts` run on every suite (`src/test/ana-bateria-regressao.test.ts`, simulated classification) and on the "Bateria de testes da Ana" page with the real model and a 12-criteria evaluator. Add a scenario for every new rule or fixed bug. Why: change, automatic test, report, fix, retest without manual chats.
